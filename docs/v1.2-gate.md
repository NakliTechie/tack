# v1.2 gate — frontier escalation + observability

Handoff §8 names the v1.2 gate as: *a stuck cheap run escalates and completes; the trace is legible.* This is the recorded evidence (scripted brains stand in for the cheap and frontier models; the live cheap-vs-frontier quality delta is owed once keys are wired).

## The economic engine (Vision §2, Catalog §3.8)

Cheap-by-default, frontier-on-escalation, ground-truth-as-arbiter. Parity between a cheap model and a frontier one *holds on verifiable tasks* (iteration against real exit codes beats raw IQ) and *breaks on judgment tasks* (a weak self-evaluator plateaus). So the loop runs the cheap model until it's stuck, then escalates — and the boundary is a visible feature, not a hidden fallback.

Two triggers (both only when a `frontier` transport is supplied):
- **doom-loop** — the cheap model repeats itself / the same error → escalate (and the cheap model's stall is recorded as an anti-pattern).
- **no ground truth** — no verify command means nothing can arbitrate, so the task is judgment-class → start on the frontier model.

Escalation is one-way (frontier is the top tier); a doom-loop *on the frontier* stops the run.

## The recording

Reproduce: `uv run python examples/demo_escalation.py`

A cheap brain keeps trying a wrong edit; after `doom_window` failures the loop escalates, and the frontier brain fixes the bug:

```
task trace — stop=verified success=True turns=4 verify=pytest -q
  ** escalated to the frontier model at turn 3
  turn  1 [cheap   ] edit    ok=False verify=False @bded3fc5
  turn  2 [cheap   ] edit    ok=False verify=False @bded3fc5
  turn  3 [cheap   ] edit    ok=False verify=False @bded3fc5
  turn  4 [frontier] edit    ok=True  verify=True  @8e203a73

cheap calls: 3  frontier calls: 1  escalated@3  success=True
```

## Gate checklist

| Requirement | Met | How |
|---|---|---|
| cheap run gets stuck | ✓ | 3 identical failing edits → doom-loop on the cheap model |
| escalates to frontier | ✓ | `result.escalated`, `escalation_turn == 3`; cheap ran 3×, frontier took over |
| completes | ✓ | frontier reaches green → `stop_reason=verified`, `success=True` |
| trace is legible | ✓ | `render_trace()` — per-turn model, action, ok, verify, git head + the escalation marker |
| judgment task → frontier | ✓ | no verify command → starts on frontier (`test_judgment_task_starts_on_frontier`) |
| no frontier → unchanged | ✓ | without a frontier, a doom-loop still stops (`test_no_frontier_means_doom_still_stops`) |

Per-step git heads in the trace are the "per-step git log + revert" surface (revert via `GitStepper.revert_to`). Covered by `tests/test_escalation.py` in the 75-test suite.
