# v1.1 gate — self-extension + local learning

Handoff §8 names the v1.1 gate as: *a task solved with a self-written tool; a known anti-pattern avoided.* This is the recorded evidence. As with v1.0, the harness mechanics are proven with a deterministic scripted brain; the live-model demonstration is owed once a key is wired.

## 1. Task solved with a self-written tool

Reproduce: `uv run python examples/demo_self_extension.py`

The agent writes a helper to `.tack/bin/`, runs it to fix the bug, and the loop promotes it:

```
workspace    : /tmp/tack-v11-XXXXXXXX
device store : /tmp/tack-home-XXXXXXXX

  turn 1: write   ok=True  verify=False  new_tools=['apply_fix']   # provisional, registered
  turn 2: bash    ok=True  verify=True   new_tools=None             # used → green → promoted

result         : success=True  stop=verified  turns=2
promoted tools : ['apply_fix']  (provisional → used in a green run → verified)
device playbook: "# Device playbook — moves that have worked before
                  - reached green on 'Fix add()…' via pytest -q; promoted tools: apply_fix"
```

| Requirement | Met | How |
|---|---|---|
| agent writes its own tool | ✓ | `write` to `.tack/bin/apply_fix` (no 5th built-in tool; `write`+`bash` suffice) |
| tool starts untrusted | ✓ | registered **provisional** on the post-step scan |
| promotion-via-verification | ✓ | used in turn 2; that turn reached ground-truth green → **verified** |
| trust re-earned on rewrite | ✓ | `test_rewritten_tool_drops_back_to_provisional` |
| state persists | ✓ | `.tack/tools.json`, reloaded across sessions |

## 2. Anti-pattern recorded, and avoided

Two on-device learning layers (no sharing transport, Vision §4.4): a per-workspace `.tack/playbook.md` injected each turn, and a per-device store (`~/.tack` / `$TACK_HOME`) carrying a cross-workspace playbook + known anti-patterns.

| Requirement | Met | How |
|---|---|---|
| anti-pattern recorded on a stall | ✓ | on `doom_loop`, `DoomLoopDetector.reason()` (e.g. `repeated action: bash:false`) is appended to the device store — `test_gate_records_anti_pattern_on_doom_loop` |
| known anti-pattern surfaced | ✓ | the store's `prior_knowledge()` is injected as a system block at session start — `test_gate_known_anti_pattern_is_surfaced_to_the_agent` |
| avoided | ✓ | the agent is told and finishes cleanly without emitting it |
| learning is local only | ✓ | plain append-only Markdown; no server, no telemetry |

Covered by `tests/test_self_extension_gate.py`, `tests/test_selfext.py`, `tests/test_learning.py` (all green in the 71-test suite).

## Bonus: a real robustness bug the gate caught

Building this gate surfaced a genuine harness bug: a same-second edit + re-test could reuse a stale `.pyc` (CPython's `.pyc` invalidation is second-resolution), making a fix invisible — which would **doom-loop the agent on already-correct code**. Fixed by `PYTHONDONTWRITEBYTECODE=1` in `NativeExecFS.run` (regression test in `tests/test_native.py`). Exactly the kind of trust-the-exit-code failure the harness must resist.
